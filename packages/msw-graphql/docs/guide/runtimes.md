# Runtimes and versions

What works with which msw, graphql, Node and Bun. Everything here was measured
in this repository unless it says otherwise.

## The tested matrix

The package's whole bar (build, typecheck, the specs under Bun, and a Node
smoke test over a real msw server including the control) passes on:

| graphql | msw | In CI |
| --- | --- | --- |
| 17.0.2 | 3.0.3 (the workspace) | yes |
| 16.14.2 | 3.0.3 | yes |
| 17.0.2 | 2.15.0 | yes |
| 16.14.2 | 2.15.0 | run by hand |

Reproduce one in a scratch copy, from the package folder:

```bash
bun run scripts/test-matrix.ts 16 3.0.3     # graphql 16, msw 3.0.3
bun run scripts/test-matrix.ts 17 2.15.0    # graphql 17, msw 2.15.0
```

Pass full versions so the installed one is unambiguous; the final `ok:` line
prints what was installed. On msw 2 the run also executes
`scripts/bun-fetch-probe.ts --expect intercepted` and fails if msw does not see
Bun's `fetch`.

`@nxgt/playwright`'s `/msw` specs pass on msw 3.0.3 with `@msw/playwright`
0.7.0. Its lower peers, msw 2.12.10 with `@msw/playwright` 0.6.7, are tested in
CI (`bun run test:lower-peers` in `packages/playwright`).

## msw 2 or msw 3

The peer is `msw ^2.12.10 || ^3.0.0`.

- msw 3 needs **Node >= 22.12**, and `graphql` is a peer of msw 3 (no longer bundled): install it.
- msw 3 renamed `onUnhandledRequest` to `onUnhandledFrame`. `startMockServer` and `enableMocking` take the old name (`start: { onUnhandledRequest }` for the worker) and pass both, so either major works.
- msw 3 moved `graphql` to `msw/graphql` and removed top-level `graphql.query` / `graphql.mutation`; only `graphql.link(url).query(...)` remains. This package uses `http.post` only, for that reason.

## Node and Bun

- **Node >= 22.12**: msw 2 and 3 both intercept `fetch`.
- **Bun**: msw 2's `setupServer` intercepts Bun's native `fetch`; **msw 3's does not** ([mswjs/msw#2811](https://github.com/mswjs/msw/issues/2811)). Its Node interceptors patch `node:net`; Bun logs `Failed to replace a global value at "_wrapHandle": not a global value.` and the request goes to the network (`ENOTFOUND`). msw's maintainer closed the issue as expected: `msw/node` is tailored to Node internals, and other runtimes should build a custom network on the `fetch/web` interceptor, which this package deliberately does not use (public API only).

  Since 0.3.0, **`startMockServer` covers it**: under Bun with msw 3 it patches `globalThis.fetch` with a wrapper that asks the handlers through msw's public `getResponse` (as `createMockFetch` does) and falls back to the original `fetch`. Same `{ server, control }`: `listen`, `close`, `use`, `resetHandlers`, `restoreHandlers`, `listHandlers`, and the `onUnhandledRequest` policies `'bypass'`, `'warn'`, `'error'` (msw's messages). It builds on `getResponse` rather than on `msw/experimental` (`defineNetwork`) or msw's interceptors on purpose: an experimental msw API may change in a minor, `getResponse` is public and stable.

  Two differences from `setupServer`, both under Bun with msw 3 only: **`server.events` and `server.boundary()` throw an error saying why** (there is no event emitter nor async context in this server; they are typed as `setupServer`'s so Node code compiles unchanged), and **only `fetch` is mocked**, so a `node:http` client (axios' Node adapter, `got`) is not. For such a client, or for your own `setupServer` calls, use `createMockFetch` from `@nxgt/msw-graphql/fetch` (patches nothing; the client must take an injected `fetch`), or msw 2. Node, and msw 2 on either runtime, keep `setupServer`, so they intercept `http`, `XMLHttpRequest` and WebSocket as before.

  Check what a plain `setupServer` does on your install:

```bash
bun -e "import{setupServer}from'msw/node';import{http,HttpResponse}from'msw';const s=setupServer(http.get('http://probe.test/x',()=>HttpResponse.json({ok:true})));s.listen({onUnhandledFrame:'bypass',onUnhandledRequest:'bypass'});fetch('http://probe.test/x').then(()=>console.log('intercepted'),()=>console.log('NOT intercepted')).finally(()=>s.close())"    # prints `intercepted` or `NOT intercepted`
```

The browser worker (`/browser`) does not depend on this, and neither do the
executor and the control, which are plain `Request` / `Response` functions.
Specs that run under Bun (`bun test`) can call them directly, as in
[control](control.md#unit-tests-without-http).

## graphql 16 or 17

Both work, as the matrix shows; the peer is `^16.0.0 || ^17.0.0`. `@graphql-tools/mock` 9.1.16 accepts both.

## `typescript-msw`

Handlers generated by `@graphql-codegen/typescript-msw` (4.0.2 and earlier,
whose peer is `msw ^2.0.0`) import `graphql` from `msw` and call
`graphql.query(...)`.

| | msw 2 | msw 3 |
| --- | --- | --- |
| `typescript-msw` handlers | work | **do not**: `TS2305 no exported member 'graphql'`, and `graphql.query` is missing |
| `@nxgt/graphql-codegen-msw` handlers | no (peer `msw ^3.0.3`) | work |
| `graphqlEndpoint(url, execute)` | works | works |

On msw 3, generate per-operation handlers with
[`@nxgt/graphql-codegen-msw`](https://www.npmjs.com/package/@nxgt/graphql-codegen-msw), or
use `graphqlEndpoint` and no generated handlers.

On **graphql 17**, `typescript-msw` 4.0.1 crashes for an operation with no
variables: `Generate [FAILED: Cannot read properties of undefined (reading 'map')]`.
4.0.2 fixes it
([graphql-code-generator-community#1653](https://github.com/dotansimha/graphql-code-generator-community/pull/1653));
upgrade and drop any `bun patch` of 4.0.1.

## Exercised in a real browser and a real Vite build

- `loadSdl` under `vite build` (`test/vite`): the `?raw` SDL is inlined in the
  output, the built module resolves it, and the Node/Bun branch reads the file.
- `enableMocking({ enabled: true })` in Chromium (`test/browser`, Playwright):
  a page under a test server registers msw's worker script and a handler built
  from `createExecutor` and `graphqlEndpoint` answers its `fetch`; with
  `enabled: false` the fetch reaches the server.

Both run in `bun run test`, on msw 3 and graphql 17 (the workspace). Neither is
part of `scripts/test-matrix.ts`, which covers the other majors with the
unit specs and the Node smoke test.
