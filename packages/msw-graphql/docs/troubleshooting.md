## `Generate [FAILED: Cannot read properties of undefined (reading 'map')]`

**When:** running `graphql-codegen` with `@graphql-codegen/typescript-msw`
4.0.1 on graphql 17, for an operation that has no variables. Reproduced with
graphql 17.0.2.
**Why:** 4.0.1 called `node.variableDefinitions.map(...)` unguarded; in
graphql 17 that field is `undefined`, not `[]`, for such an operation.
**Fix:** upgrade to `@graphql-codegen/typescript-msw` 4.0.2 or later, which
guards the field
([dotansimha/graphql-code-generator-community#1653](https://github.com/dotansimha/graphql-code-generator-community/pull/1653)).
Drop any `bun patch` of 4.0.1 (`patches/@graphql-codegen%2Ftypescript-msw@4.0.1.patch`
and its `patchedDependencies` entry) at the same time. The upgrade only makes
the generator run: 4.0.2 still declares `msw ^2.0.0` and its output still
targets msw 2's `graphql.query` (next entry).

## `Module '"msw"' has no exported member 'graphql'`

**When:** type-checking or importing handlers generated by
`@graphql-codegen/typescript-msw` (4.0.2 and earlier) on msw 3 (`TS2305`, or
`graphql.query` is missing).
**Why:** msw 3 removed the top-level `graphql.query` / `graphql.mutation` and
moved `graphql` to `msw/graphql`; only `graphql.link(url).query(...)` remains.
The generated handlers use the msw 2 API. Measured, not a guess.
**Fix:** on msw 3, generate the per-operation handlers with
[`@nxgt/graphql-codegen-msw`](https://www.npmjs.com/package/@nxgt/graphql-codegen-msw),
which targets msw 3, instead of `typescript-msw`. Or skip generated handlers:
one catch-all handler executes the real operations:

```ts
import { graphqlEndpoint } from '@nxgt/msw-graphql';

export const handlers = [graphqlEndpoint(API_URL, execute)];
```

Or stay on msw `^2.12.10`, where the generated handlers work.

## msw 3 needs Node >= 22.12

**When:** installing or running with msw 3 on an older Node (the package
manager reports an unsupported engine).
**Why:** msw 3.0.3 declares `engines.node >= 22.12`. The exact engines
message depends on the package manager and was not reproduced here.
**Fix:** upgrade Node to 22.12 or later, or stay on msw 2:

```bash
bun add -d msw@^2.12.10
```

## `Failed to replace a global value at "_wrapHandle": not a global value.`

**When:** a plain `setupServer` from `msw/node` (msw 3) under Bun, or
`startMockServer` from a version of this package before 0.3.0. The message is
logged, the request is not mocked and goes to the network (`ENOTFOUND`).
Measured.
**Why:** msw 3's Node server patches `node:net`, which does not intercept
Bun's native `fetch` (msw 2.15 does). msw closed
[mswjs/msw#2811](https://github.com/mswjs/msw/issues/2811) as expected.
**Fix:** `startMockServer` patches `fetch` itself under Bun with msw 3 since 0.3.0:
upgrade `@nxgt/msw-graphql`. It patches `globalThis.fetch` only, so a client
built on `node:http` (axios' Node adapter, `got`) is not mocked under Bun; give
such a client `createMockFetch`'s fetch, or run it under Node:

```ts
import { createMockFetch } from '@nxgt/msw-graphql/fetch';

const { fetch, control } = createMockFetch(handlers);
const client = createClient({ url, fetch }); // your API client
```

For your own `setupServer` calls (outside `startMockServer`), see
[runtimes](guide/runtimes.md#node-and-bun). To check what a plain `setupServer`
does on your install:

```bash
bun -e "import{setupServer}from'msw/node';import{http,HttpResponse}from'msw';const s=setupServer(http.get('http://probe.test/x',()=>HttpResponse.json({ok:true})));s.listen({onUnhandledFrame:'bypass',onUnhandledRequest:'bypass'});fetch('http://probe.test/x').then(()=>console.log('intercepted'),()=>console.log('NOT intercepted')).finally(()=>s.close())"   # prints "intercepted" or "NOT intercepted"
```

The probe lives in this package's `scripts/` folder in the repository.

## `@nxgt/msw-graphql: server.events is not available under Bun with msw 3`

**When:** reading `server.events` on the server `startMockServer` returns,
under Bun with msw 3.
**Why:** under Bun with msw 3 the server patches `globalThis.fetch` and resolves
requests with msw's public `getResponse`. It has no event emitter nor async
context; it is the one difference from `setupServer`, and it is typed as
`setupServer`'s so Node code compiles unchanged.
**Fix:** run that code under Node or msw 2, or observe requests in a handler.
`listen`, `close`, `use`, `resetHandlers`, `restoreHandlers` and `listHandlers`
work.

## `@nxgt/msw-graphql: server.boundary() is not available under Bun with msw 3`

**When:** calling `server.boundary()` on the server `startMockServer` returns,
under Bun with msw 3.
**Why:** same as `server.events`: this server has no async context to scope.
**Fix:** run that code under Node or msw 2, or isolate state per test with
`resetHandlers()`.

## `createMockFetch: no handler for <METHOD> <url>.`

**When:** `createMockFetch(handlers, { strict: true })` gets a request that no
handler matches (a handler that calls `passthrough()` is not one: that request
goes to `fallback`).
**Why:** with `strict`, an unhandled request throws instead of going to the
real `fetch` (or to `fallback`).
**Fix:** add a handler for that URL, or drop `strict` so that it passes through:

```ts
const { fetch } = createMockFetch(
	[...handlers, http.get('https://cdn.example.test/*', () => new Response(null, { status: 204 }))],
	{ strict: true },
);
```

## `[MSW] Cannot bypass a request when using the "error" strategy for the "onUnhandledRequest" option.`

**When:** `startMockServer(handlers, { onUnhandledRequest: 'error' })` (or
`server.listen({ onUnhandledRequest: 'error' })`) and the app sends a request no
handler matches: the `fetch` rejects with this error, after msw printed
`[MSW] Error: intercepted a request without a matching request handler`. Thrown
by this package's server under Bun with msw 3, and by msw's own server under
Node (msw 3 words it with `"onUnhandledFrame"`). `createMockFetch` never throws
it: its equivalent is `strict` ([no handler](#createmockfetch-no-handler-for-method-url)).
**Why:** `'error'` fails the request instead of sending it for real. The
request is unhandled by design: a handler that calls `passthrough()` does not
count, and neither does `fetch(bypass(request))` inside a resolver.
**Fix:** add a handler for that URL, let it through explicitly, or use
`'bypass'` (`startMockServer`'s default; a direct `server.listen()` defaults
to `'warn'`, as msw does) or `'warn'`:

```ts
import { http, passthrough } from 'msw';

startMockServer(
	[...handlers, http.get('https://cdn.example.test/*', () => passthrough())],
	{ onUnhandledRequest: 'error' },
);
```

## `Failed to call "server.listen()": the server is already listening.`

**When:** calling `server.listen()` on the server `startMockServer` returned.
msw 3 words it `... Remove the redundant "server.listen()" call.`; under Bun
with msw 3 this package throws the shorter message above.
**Why:** `startMockServer` already calls `listen()` for you, and it is
idempotent per process: a second `startMockServer` call returns the first
`{ server, control }`.
**Fix:** drop the `listen()` call. To stop and start again, `close()` first
(which also forgets the server, so the next `startMockServer` starts a new one):

```ts
const { server } = startMockServer(handlers);
// no server.listen() here: it is already listening
server.close();
```

## `Failed to react to an unhandled request: unknown strategy "<value>"`

**When:** `server.listen({ onUnhandledRequest: value })`, or
`startMockServer(handlers, { onUnhandledRequest: value })`, where `value` is
not `'bypass'`, `'warn'` or `'error'`: a typo, or an unchecked string such as an
environment variable. Under Bun with msw 3 the message is the one above; msw 3's
own server on Node says `unknown strategy "<value>" ... network frame`
and also accepts a callback function (this package's `startMockServer` type
does not).
**Why:** the option is validated when `listen()` runs. Under Bun nothing is
patched when it throws, so `fetch` stays the real one.
**Fix:** pass one of the three strategies:

```ts
const strategy = process.env.MOCK_UNHANDLED;
startMockServer(handlers, {
	onUnhandledRequest: strategy === 'error' || strategy === 'warn' ? strategy : 'bypass',
});
```

## `createMockControl is dev and test only: NODE_ENV is "production"`

**When:** calling `createMockControl`, `startMockServer` or `createMockFetch`
(both build the control first) with `NODE_ENV=production` or in a Vite production build
(`import.meta.env.PROD`). The guard fails open when `NODE_ENV` is unset, as under Bun. A mounted control also answers
`404` to every `/__mocks` route in production.
**Why:** the control can reset, fail and reseed the API; it must never run in
a production build.
**Fix:** import `/node`, `/fetch` and `/control` only behind your mocks flag, with a
dynamic import (on a server; in a Vite client build the condition must be
statically false, see the Production section of the control guide):

```ts
if (process.env.MOCKS === 'true') {
  const { startMockServer } = await import('@nxgt/msw-graphql/node');
  const { control } = startMockServer(handlers);
}
```

Run the mocked server (and the e2e suite) with `NODE_ENV` not `production`.

## The control answers 415, 404, 405 or 400

**When:** calling `POST /__mocks/<route>` directly, or through
`mockServer` in `@nxgt/playwright/mock-server`, which throws
`/__mocks/<route> answered <status>: <body>`.
**Why:** the body is a JSON `{ "error": "..." }` naming the cause:

| Answer | Message | Cause |
| --- | --- | --- |
| `415` | `The body must be application/json.` | any POST without a `content-type: application/json` header, an empty `reset` included |
| `404` | empty | an unknown route (only `reset`, `fail`, `scenario`, `override`), or any route in production (`NODE_ENV=production` or `import.meta.env.PROD`) |
| `404` | `No scenario "x". Registered: a, b.` | the scenario name is not in the `scenarios` you passed (`none` when there are none) |
| `405` | `POST only.` | any method other than `POST` |
| `400` | `The body is not JSON.` | the body does not parse |
| `400` | `` `status` must be an HTTP status (100-599) or null. `` | `fail` with another value |
| `400` | `` `name` must be a string. `` | `scenario` without a name |
| `400` | `Each override needs an \`operationName\` string.`, `` `status` must be an HTTP status (100-599). ``, `` `errors` must be an array. ``, `` `once` must be a boolean. `` | an invalid override |
| `500` | the thrown message | your reset or scenario function threw |

**Fix:** send JSON with its header, and register the scenario:

```ts
const control = createMockControl({ server, scenarios: { empty: emptyMocks } });
await fetch('http://localhost:3000/__mocks/scenario', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ name: 'empty' }),
});
```

If every route is `404`, the control is not mounted at that path:
`app.all('/__mocks/*', ({ request }) => control.handle(request))`.

## Mock-server specs fail when run in parallel

**When:** specs that use `mockServer` are flaky or fail when several workers
hit one app server. In this repository the mock-server spec failed 11 of 18
when run in parallel with the other specs.
**Why:** server mocks (`fail`, `scenario`, `use`, the reset around each test)
are process-global; workers overwrite one another.
**Fix:** run those projects with one worker, or give each worker its own server:

```ts
// playwright.config.ts
export default defineConfig({ workers: 1, fullyParallel: false });
```

## My second `startMockServer` call's handlers or options are ignored

**When:** `startMockServer(handlers, options)` runs twice in one process (an
SSR entry module re-evaluated by HMR, or two specs) and the second call's
handlers, `onUnhandledRequest` or `reset` seem to do nothing.
**Why:** it is idempotent per process by design: the second call returns the
first call's `{ server, control }`, and its arguments are ignored.
**Fix:** change the running server, or close it first:

```ts
const { server, control } = startMockServer(handlers);
server.use(...moreHandlers); // or control.reset()

server.close(); // the supported way to stop; the next call starts a new server
const next = startMockServer(otherHandlers, { onUnhandledRequest: 'error' });
```

Do not call `listen()` again on a closed server: it intercepts again but is not
registered, so the next `startMockServer` starts a second server beside it.

## `loadSdl needs a \`vite\` callback, a \`file\`, or both.`

**When:** calling `loadSdl({})`. Related: in Node or Playwright the SDL is
not found (`ENOENT`, or `loadSdl: no \`file\` to read.`).
**Why:** under Vite the `vite` callback (a `?raw` import) loads the schema;
elsewhere the `file` is read with `node:fs`. With neither there is nothing to
load, and under Node a `vite`-only call has no file to fall back to. The
Vite branch is detected by `import.meta.env` (boolean `DEV`, string
`BASE_URL`), by `window`, or by a missing `file`; a spec builds a fixture with
`vite build` and checks the SDL is inlined and resolves from the built module.
**Fix:** pass both, with the `?raw` import kept as a literal:

```ts
import { loadSdl } from '@nxgt/msw-graphql/sdl';

const sdl = await loadSdl({
  vite: () => import('../schema.graphql?raw'),
  file: new URL('../schema.graphql', import.meta.url),
});
```

## `Cannot use GraphQLSchema "[object GraphQLSchema]" from another module or realm`

**When:** executing or building a schema when two copies of `graphql` are
installed (for example 16 and 17). Not reproduced for this page; it is
graphql's own check.
**Why:** the schema was built with one copy and executed with another.
**Fix:** keep one copy, aligned with the peer range `^16 || ^17`:

```bash
bun why graphql          # list the copies
bun add graphql@^17      # one version everywhere
```

## A subscription test hangs, or a stream never ends

A scripted stream ends when its iterator ends. If the test's generator waits on
a promise that never settles, the stream stays open; `control.reset()`
(or `closeStreams(state)`) closes the client's side, but a generator parked in
an `await` only returns once that settles. Script waits with `setTimeout` or an
abortable promise. A request without `Accept: text/event-stream` is not
streamed either: send the header.
