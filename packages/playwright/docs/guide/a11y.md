# Accessibility

`@nxgt/playwright/a11y` runs [axe](https://github.com/dequelabs/axe-core) on
the page a spec has open, through `@axe-core/playwright`, and fails with a
message you can act on without opening a report.

```bash
bun add -d @axe-core/playwright
```

`@axe-core/playwright` is an optional peer (`>=4.10.0 <5`): only this subpath
needs it, which is also why the root `@nxgt/playwright` does not re-export it.

```ts
import { expect, test } from '@playwright/test';
import { expectAccessible } from '@nxgt/playwright/a11y';

test('projects page is accessible', async ({ page }) => {
	await page.goto('/projects');
	await expect(page.getByTestId('projects')).toBeVisible();
	await expectAccessible(page);
});
```

## Signatures

```ts
type DisabledRule = { rule: string; reason: string };

type A11yOptions = {
	include?: string | readonly string[];
	exclude?: string | readonly string[];
	disableRules?: readonly DisabledRule[];
	tags?: readonly string[];
};

type ExpectAccessibleOptions = A11yOptions & { testInfo?: TestInfo };

function expectAccessible(
	page: Page,
	options?: ExpectAccessibleOptions,
): Promise<AccessibilityResults>;

function accessibilityScan(page: Page, options?: A11yOptions): Promise<AccessibilityResults>;

type A11yFixtures = {
	a11y: {
		expect(options?: A11yOptions): Promise<AccessibilityResults>;
		scan(options?: A11yOptions): Promise<AccessibilityResults>;
	};
};

// The test you pass, its fixtures kept, plus `a11y`.
function withA11y<T extends PlaywrightTestArgs, W extends object>(
	test: TestType<T, W>,
): TestType<T & A11yFixtures, W>;

function formatViolations(
	violations: readonly ViolationSummary[],
	options?: { url?: string; tags?: readonly string[]; maxNodes?: number },
): string;

const DEFAULT_TAGS: readonly string[]; // wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa
```

`AccessibilityResults` is axe's own result object: `violations`, `passes`,
`incomplete`, `inapplicable`, `url`, `timestamp`, …

## Options

| Option | Type | Default | Effect |
| --- | --- | --- | --- |
| `include` | `string \| string[]` | the whole page | Only scan inside these CSS selectors. |
| `exclude` | `string \| string[]` | nothing | Leave these out: a third-party widget, a region another spec covers. |
| `disableRules` | `{ rule, reason }[]` | none | Turn axe rules off. **Each needs a reason** — see below. |
| `tags` | `string[]` | `DEFAULT_TAGS` | The axe tags to run instead of WCAG 2.0, 2.1 and 2.2 at A and AA. |
| `testInfo` | `TestInfo` | the running test's | Where the report is attached (`expectAccessible` only). |

### What is checked by default

The rules axe tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa`:
WCAG 2.2 level AA, which includes A. axe's `best-practice` rules (such as
`region`, every content inside a landmark) are not in it; ask for them:

```ts
import { DEFAULT_TAGS, expectAccessible } from '@nxgt/playwright/a11y';

await expectAccessible(page, { tags: [...DEFAULT_TAGS, 'best-practice'] });
```

`tags` replaces the default, it does not add to it.

### Disabling a rule takes a reason

```ts
await expectAccessible(page, {
	disableRules: [
		{ rule: 'color-contrast', reason: 'brand palette under review, tracked in #42' },
	],
});
```

A bare rule id, or an entry without `reason`, is a **type error**; a JavaScript
caller, or a blank reason, gets a run-time error instead:

```
disableRules: "color-contrast" is disabled without a reason. Give it as { rule: 'color-contrast', reason: 'why it is off here' }.
```

The reason is for the next reader of the spec: an exception nobody can explain
is never removed. Rule ids are axe's —
[the rule list](https://github.com/dequelabs/axe-core/blob/develop/doc/rule-descriptions.md).

### `include` and `exclude`

```ts
await expectAccessible(page, { include: 'main', exclude: ['#chat-widget', '.ad-slot'] });
```

Prefer `exclude` for markup you do not own over disabling a rule for the whole
page.

## The failure

```
1 accessibility violation on http://localhost:5174/projects (wcag2a, wcag2aa, wcag21a, wcag21aa, wcag22aa):

1. image-alt [critical] Images must have alternative text
   https://dequeuniversity.com/rules/axe/4.13/image-alt
   - #logo
     <img id="logo" src="/logo.png">
   - .card:nth-child(2) > img
     <img src="/projects/2.png">
   … and 4 more nodes
```

One block per rule: its id, impact, what to do, where to read more, and the
first three nodes with their selector and HTML (cut to 200 characters). A node
inside an iframe reads `iframe#app -> img`; inside a shadow root,
`my-card >>> img`.

The full axe results are attached to the test as `accessibility-scan.json`:
open the HTML report, the failing test, then the attachment. Outside a test
(a global setup, a script), nothing is attached; pass `testInfo` to choose
where it goes.

## `accessibilityScan`: the results, without asserting

For a check of your own — a budget, a rule you only want to warn about, a
report across pages:

```ts
import { expect, test } from '@playwright/test';
import { accessibilityScan, formatViolations } from '@nxgt/playwright/a11y';

test('no new serious issues', async ({ page }) => {
	await page.goto('/projects');
	const { violations } = await accessibilityScan(page);
	const serious = violations.filter((v) => v.impact === 'serious' || v.impact === 'critical');
	expect(serious, formatViolations(serious)).toEqual([]);
});
```

It validates `disableRules` the same way.

## The `a11y` fixture

```ts
// playwright/config/playwright.setup.ts
import { test as base } from '@playwright/test';
import { withA11y } from '@nxgt/playwright/a11y';

export const test = withA11y(base);
export { expect } from '@playwright/test';
```

```ts
// playwright/e2e/projects.spec.ts
import { test } from '../config/playwright.setup';

test('projects page is accessible', async ({ page, a11y }) => {
	await page.goto('/projects');
	await a11y.expect({ exclude: '#chat-widget' });
	const results = await a11y.scan(); // accessibilityScan, bound to the page
});
```

`withA11y` composes with the other fixtures: `withA11y(createMswTest(handlers))`,
`withA11y(withLoginFixture(base, SignInPage))`.

## Scanning at the right moment

axe reads the page as it is when it runs.

- **Wait for the content.** A scan right after `goto()` may see a loading
  state. Assert what the page shows first (`toBeVisible()`), then scan.
- **Wait for transitions and animations to end.** A fade-in scanned
  half-way reports `color-contrast` against a colour that is never shown at
  rest. Wait for the final state, or turn motion off for the scan:

  ```ts
  test.use({ reducedMotion: 'reduce' }); // when the app honours prefers-reduced-motion
  ```

- **Scan each state you care about.** An open dialog, an error message, a
  menu: open it, then scan — each is a different page for axe.
- **Phones too.** On a `mobile-chromium` project
  ([config.md](config.md#mobile)), the same spec scans the phone layout.
